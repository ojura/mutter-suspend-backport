Comment for https://bugs.launchpad.net/ubuntu/+source/mutter/+bug/2174026, with out/mutter_46.2-1ubuntu0.24.04.19.debdiff attached (patch box checked). Before posting, untick the patch flag of the first debdiff (attachment 6017163) or retitle it, so that a sponsor does not pick it up.

The debdiff I attached on 2026-11-12 can crash gnome-shell; please use mutter_46.2-1ubuntu0.24.04.19.debdiff, attached here, instead.

The first backported commit connects a notify::mapped handler to every surface actor of a window and never disconnects it. 46.2 keeps the surface actor when a client creates a new xdg_toplevel or xdg_popup on the same wl_surface (mutter 47 creates a new one, merge request 3667), so showing the new window runs the handler with the freed window actor of the destroyed one. With 46.2-1ubuntu0.24.04.18+local1 this crashed gnome-shell twice in one day, after Telegram Desktop and an Electron application had each created a new toplevel on an old wl_surface.

The new debdiff adds upstream merge request 5347 (https://gitlab.gnome.org/GNOME/mutter/-/merge_requests/5347, not merged yet), which disconnects the handler, and a test case that shows two toplevels one after the other on the same wl_surface. Run alone, the case fails in 9 of 10 runs without the fix, and with AddressSanitizer it reports a heap-use-after-free in is_surface_actor_mapped_changed(); with the fix it passes in all 10 runs and under AddressSanitizer. The package build gives the same test results as with the first debdiff, and so do the 66 checks in the headless shell. I built and tested this source as 46.2-1ubuntu0.24.04.18+local2; the debdiff differs from it only in the changelog entry and in the Bug-Ubuntu lines of the patch headers. The description now lists the two new patches.
